### 1.2 業態外・マクロ指標の位置づけ

`cpi` は業態（店舗の売上統計）ではないため §1.1 表の `種別` 列で `macro` として明示している。同様に `ec-platform`（年度ベースの市場規模推計）も店舗の既存店/全店統計ではないため `macro` に分類する。ダッシュボード側は `種別=macro` の系列を業態トレンド（既定=`association`）とは別軸で表示すること（要件定義書 §7-4 対応）。

### 1.4 同一業態に複数の発表主体が存在するケース（natural key への `発表主体` 追加を踏まえて）

`発表主体` が natural key の一部になる設計（`(segment_id, metric_id, source_authority, scope, period_key)` 相当）を前提に、同一 `segment_id` に対して複数の発表主体が並立し得るケースをここに明記する。**これは重複でも取りこぼしでもなく、母集団の異なる別系列として両方を保持すべきもの**である。

| segment_id | 発表主体A | 発表主体B | 扱い |
|---|---|---|---|
| `home-center` | 業界紙（DCS）集計 | 経済産業省（商業動態統計） | 対象企業母集団が異なるため数値は一致しない。両方とも `entity_type=association` の正当な観測として `発表主体` 違いで別系列に保持する（§1.1 home-center 行の定義列に既述） |
| `drugstore` | 経済産業省（商業動態統計） | 個社開示（コスモス薬品、ツルハ等） | 個社開示は `種別=company` 相当だが v0.1 では個社 segment 行を追加しない方針（§1.5 参照）のため、当面は経産省ソースのみを `drugstore` segment の観測として扱い、個社決算は `out_of_scope` 分類とする |

**`meti-commerce-dynamics` と各業態 segment の関係についての結論**: `meti-commerce-dynamics` は「小売業全体」という独立した集計区分を指す segment であり、`electronics-retailer` 等の個別業態の**親ではない**。経産省が家電大型専門店・ドラッグストア・ホームセンター等の業態別内訳を発表する場合、その観測は各業態の segment（`electronics-retailer` 等）に `発表主体=経済産業省` として記録し、`meti-commerce-dynamics` segment には計上しない。これにより「小売業全体」の値と業態別内訳の値が二重計上されることを防ぐ。

### 1.5 `種別=company`（個社）行の書き方（将来拡張用、現時点では行を追加しない）

案1 側の方針により、個社を segment として当面カタログ化しない（個社決算記事は `out_of_scope` として除外表示する）。将来、頻出上位の個社を追加する場合の書き方の想定のみ以下に示す。

- `segment_id`: 企業名の kebab-case（例: `takashimaya`、`seven-eleven`）
- `種別`: `company`
- `上位業態`: 属する業態の segment_id（例: セブン-イレブンなら `convenience-store`）
- `発表主体`: 当該企業名そのもの（個社開示は発表主体＝観測対象企業と一致するため）

## 2. KPI 定義

### 2.1 KPI 一覧

IF-02 カタログスキーマ契約に従い、`metric_id` / `名称` / `単位` / `値種別` / `方向` / `別名` / `既定スコープ` / `小数桁` の 8 列を必須列とする。`値種別` は `ratio`（比率・前年比）/ `absolute`（絶対額）、`方向` は `higher_is_better` / `lower_is_better` / `neutral` の enum 値をそのまま記載する。`既定スコープ` は日本語ラベル（既存店/全店/総供給高/該当なし）を維持し、案1 の scope enum（`existing_store` 等）への変換は §4.5 の対応表に分離する。`単位` も同様に日本語表記（%、億円等）を維持し、unit enum への変換は §4.4 に分離する。

| metric_id | 名称 | 別名 | 単位 | 値種別 | 方向 | 既定スコープ | 小数桁 | 主な適用業態 | 解釈上の注意 |
|---|---|---|---|---|---|---|---|---|---|
| `existing-store-sales-yoy` | 既存店売上高前年比 | 既存店売上, 既存店売上高, 既存店 | % | ratio | higher_is_better | 既存店 | 1 | 全業態・全個社 | 業界で最も引用頻度が高い指標。開店から一定期間（一般に13ヶ月以上）経過した店舗のみが対象で、新規出店・閉店の影響を除去した「同一店舗ベース」の伸び率 |
| `all-store-sales-yoy` | 全店売上高前年比 | 全店売上高, 総売上高前年比, 外食売上, チェーンストア販売 | % | ratio | higher_is_better | 全店 | 1 | 経産省統計、一部協会 | 新規出店分を含むため、既存店が減収でも全店は増収になり得る。両者を混同すると出店戦略の効果と既存店の実力を取り違える。`外食売上`（日本フードサービス協会の外食産業市場動向調査）と `チェーンストア販売`（日本チェーンストア協会）は、見出しに「既存店」の文字列がない業態全体の集計値であるため、§2.2 の判定ルールに従い既存店指標には昇格させず本 KPI に割り当てる |

### 2.2 既存店 / 全店の区別（最重要ルール）

小売統計で最も誤読されやすいポイントであるため、KPI 定義上も独立した指標として明確に分離する。

| 観点 | 既存店（existing store） | 全店（all store） |
|---|---|---|
| 対象店舗 | 開店から一定期間（一般に13ヶ月以上）経過した店舗のみ | 新規出店・閉店を含む全店舗 |
| 何を測る指標か | 店舗運営そのものの実力（同一店舗の売上変化） | 出店戦略込みの事業規模の変化 |
| 典型的な乖離パターン | 既存店マイナスでも全店はプラスになり得る（新規出店が下支え） | 既存店プラスでも閉店が多ければ全店はマイナスになり得る |
| ダイジェストでの表記 | 「既存店」「既存店売上高」と明記されるケースがほとんど | 「総売上高」「売上高」「販売額」など、既存店の明記がない表現に多い |
| 判定ルール | 見出し・本文に「既存店」の文字列があれば `existing-store-sales-yoy` | 「既存店」の記載がなく単に「売上高」「総売上高」「販売額」であれば `sales-amount-absolute` または `all-store-sales-yoy`（絶対額か率かでさらに分岐） |

**トラッカー実装への申し送り**: 記事本文に「既存店」の文字列が**ない**限り、既存店指標として扱わない（推測でラベル付けしない）。カスミ「総売上高233億円、既存店売上2.3%減」のように 1 記事内に両方の指標が併存する場合は、2 レコードに分割して格納すること。

**§2.1 と本節の適用順序（実装者向け明示）**: この判定順序は小売実務として正しい。§2.1 の `既定スコープ` は「その `metric_id` が採用された後に scope へ機械的に割り当てる値」であり、`metric_id` そのものをどう決めるかには関与しない。`metric_id` の決定は本節（§2.2）の判定ルールが優先する。すなわち「6月既存店1.7%減」→ 見出しに「既存店」があるため `metric_id=existing-store-sales-yoy` を採用し、§2.1 の既定値どおり `scope=existing_store` を割り当てる。「6月の売上高2.3%増」→ 見出しに「既存店」がないため `existing-store-sales-yoy` に**昇格させることを禁止**し、率であれば `all-store-sales-yoy`、絶対額であれば `sales-amount-absolute` を採用する（後者は既定 `scope=n_a`、§4.5 参照）。実務上、既存店表記のない見出しを既存店統計として扱うことが最も頻発する誤読（§3-1）であるため、この優先順位を逆にしてはならない。

## 3. ドメイン上の落とし穴

SIer が本データを提案・分析に使う際に誤読しやすい点。優先度が高い順に記載する。

1. **既存店と全店の混同**（§2.2 参照）。「増収」という見出しだけで既存店の実力も伸びていると解釈しないこと。特に持株会社決算（イオン、セブン＆アイ）は新規出店・M&A（例: イオン九州のジョイフルサン吸収合併）の影響が大きく、既存店統計とは別軸で読む必要がある。

2. **前年同月比と前月比の混同**。ダイジェストで確認できた小売月次統計は**ほぼ全て前年同月比（YoY）**であり、前月比（MoM）表記はほぼ登場しない。季節変動が大きい小売では前月比の方が実務上ミスリードになりやすいため、統計側もYoYを標準としている。トラッカーで前月比グラフを作る場合はYoY系列から独自に導出する必要があり、公表値そのままではない点に注意。

3. **うるう年・曜日並び・祝日移動の影響**。前年同月と当年同月で土日・祝日の日数構成が異なると、既存店売上高（特に外食・SC等の週末型消費が強い業態）が実力以上に振れる。ダイジェスト中でも「前年より休日数増」（2026-06-26 ショッピングセンター 5月+9.9%増の一因）が明記されており、伸び率の大小をそのまま実力差と解釈しないこと。

4. **天候要因、特に「前年の天候」との比較基点のズレ、および他要因との混同**。2026年6月は複数業態で「天候不順」による客数減が要因として挙げられている（ショッピングセンター、チェーンストア、PPIH、イオンリテール等）。一方で猛暑は空調・生活家電需要を押し上げる例が確認できるが、参照する数値の**対象月・他要因との混在**に注意が必要。
   - 「家電大型専門店／5月の販売額は27.5%増、生活家電が41%増に」（流通ニュース、`.companies/domain-tech-collection/docs/daily-digest/2026-06-30.md` 掲載、URL: `https://www.ryutsuu.biz/sales/s062944.html`）は**対象月が2026年5月**であり、6月の天候不順の議論と混在させないこと。
   - 「DCM 決算／3〜5月営業利益17.4%増、中東情勢影響のまとめ買い・空調関連などで」（流通ニュース、`.companies/domain-tech-collection/docs/daily-digest/2026-06-27.md` / `2026-06-28.md` 掲載、URL: `https://www.ryutsuu.biz/accounts/s062681.html`）は実在する記事だが、**中東情勢によるまとめ買い需要と猛暑による空調需要の両方**が要因として併記されており天候のみが原因ではない。また対象が暦月（6月）ではなく**企業の会計四半期（3〜5月期）の決算**である点も§3-7 の期間粒度の論点と重なる。
   - **「今年の天候」だけでなく「前年同月の天候」も比較基点として影響する**（前年が猛暑だった場合、今年が平年並みでも夏物商品は「不調」に見える）。天候コメントが付く記事は、対象月・対象期間・他要因との混在を確認したうえで単純に当年天候だけで説明を組み立てないこと。

5. **インバウンド比率の高い業態（百貨店）と低い業態の比較不能性**。百貨店はインバウンド売上と国内顧客売上を分離公表する唯一の業態（ダイジェスト確認範囲内）。他業態（コンビニ、スーパー、チェーンストア）はインバウンド内訳を公表しないため、「百貨店は国内客が弱いのに全体は伸びている」という構造を他業態と横並びで比較すること自体ができない。業態横断ダッシュボードでインバウンド比率を推定表示する場合は「百貨店のみ実測、他は非公開」と明示すること。

6. **消費者物価指数（CPI）と売上前年比を比較する際の実質・名目の混同**。既存店売上高＝客数×客単価（概算）であり、客単価の上昇には①値上げ（価格転嫁、名目要因）と②購入点数・購入商品構成の変化（実質要因）が混在する。CPIの上昇率（例: 2026年6月 +1.6%）と客単価上昇率を単純に差し引きして「実質購買量」を語ると、業態別の物価バスケット構成がCPI総合とは異なる点を見落とす。

7. **決算（四半期・会計年度ベース）と月次店舗統計（暦月ベース）の期間粒度の混同**。個社決算は「3〜5月期」のような会社の会計四半期で示されるのに対し、既存店統計は暦月（6月単月）。同じ「6月」を含む数字でも集計期間が異なるため、決算コメントと月次既存店コメントをそのまま同一の時系列グラフに繋げない。

8. **経産省 商業動態統計と各業界団体統計の対象母集団の違い**（§1.1 参照）。同じ「百貨店」「スーパー」「ドラッグストア」という業態名でも、経産省統計（全国調査ベース）と各協会統計（会員社ベース）は調査対象企業数・店舗数が異なり、伸び率が一致しないことが常態。数値の乖離を「異常値」と誤判定しないこと。

## 4. 正規化ルール表

### 4.1 増減表記 → 符号付き数値への正規化

| 表記パターン | 正規化ルール | 例 |
|---|---|---|
| 「X.X%増」 | `+X.X` | 「1.6%増」→ `+1.6` |
| 「X.X%減」 | `-X.X` | 「1.6%減」→ `-1.6` |
| 「横ばい」 | `0.0`（※業界一般知識による補足: 公表上「横ばい」は概ね±0.1〜0.2%未満の変動を指すことが多く、正確な数値は原資料で要確認） | 「6月の既存店売上高横ばい」→ `0.0`（要出典確認フラグを立てる） |
| 「◯割増」 | `+◯0.0`（割＝10%換算） | 「3割増」→ `+30.0` |
| 「半減」 | `-50.0` | 「貿易赤字が半減」→ `-50.0` |
| 「◯カ月ぶりの前年割れ」等の連続記録表現 | YoY数値そのものではなく付帯メタ情報として別フィールド（例: `streak_broken_months`）に保持する | 「51カ月ぶりに前年割れ」→ `existing-store-sales-yoy = -1.6` かつ `streak_broken_months = 51` |
| 定性表現のみ（「増収増益」「減収減益」等） | 数値化不可。`sign_only` フィールドに `+`/`-` のみ記録し、数値は原資料参照のフラグを立てる | 「しまむら 3〜5月増収増益」→ `operating-revenue-yoy: sign_only=+`, `operating-profit-yoy: sign_only=+` |

**v0.1 運用注記**: `streak_broken_months` および `sign_only` は observations の nullable 列として保持し、**v0.1 から SC-01 概観ダッシュボードのハイライト帯における文章表示に使用する**（例: 「SC が 51 カ月ぶりに前年割れ」、要件定義書 §5.3 SC-01・§7-11 準拠）。時系列チャートの軸・凡例など**グラフ系列としての活用は v0.2 以降**の対応とする。

### 4.2 対象年月の抽出・正規化

| 表記パターン | 正規化ルール | 例 |
|---|---|---|
| 「6月」（単独、月名のみ） | 記事の掲載月の**前月**を対象年月とする（小売月次統計は前月分が翌月下旬に発表される） | 掲載日 2026-07-25 の記事「6月既存店」→ 対象年月 `2026-06` |
| 「2026年6月度」 | 明示された年月をそのまま採用 | → `2026-06` |
| 「3〜5月」（企業決算の会計四半期） | `target_period_type = "quarter"` とし、開始月・終了月をそのまま保持（会社の決算期に応じ暦年基準ではないため月次に丸めない） | → `2026-03`〜`2026-05`, `period_type=quarter` |
| 「1〜6月期」（暦年上半期） | `target_period_type = "half"` | → `2026-01`〜`2026-06` |
| 「2025年度」（会計年度） | 日本の会計年度（4月始まり）として `YYYY-04`〜`(YYYY+1)-03` に変換し `period_type = "fiscal_year"`、`period_key = "FY{year}"` | 「2025年度」→ `2025-04`〜`2026-03`, `period_key = "FY2025"` |
| 「◯◯年◯月期」（単月表記の企業会計期、決算期末月） | 決算月を会計年度の期末とみなし `period_type = "fiscal_year"`（「2025年度」と同一区分。会計年度の名付け方が異なるのみでドメイン上の別区分ではない）、`period_key = "FY{year}-{month}"` の形式で保持する。西暦2桁表記（「29年」）は2000年代として補完する | 「DCM／29年2月期売上高6500億円・営業利益423億円目標」→ `period_type = "fiscal_year"`, `period_key = "FY2029-02"` |
