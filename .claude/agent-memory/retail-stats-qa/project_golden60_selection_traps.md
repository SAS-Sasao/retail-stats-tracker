評価データセットの「機械的選定」を採点するときに毎回確かめる観点。2026-08-02 の
レビューで実測により確認したもの。

1. **URL 昇順のタイブレークは中立ではない。** URL 文字列昇順 = ドメインのアルファベット順
   であり、記事の性質と相関する。本データでは `diamond-rm.net`（個社決算・ランキング中心、
   母集団 17.5%）が常に先頭、`www.ryutsuu.biz`（協会統計・経産省統計のほぼ全て、母集団 57.6%）
   が常に最後尾になり、選定は 46.7% / 33.3% に反転した。サイト内でも
   `/market/accounting/`（決算ランキング）が `/retaildata/`（月次統計）より先に来る。
   さらに各サイトの記事 ID は時系列昇順なので、候補が多い区分ほど古い月に寄る。

2. **`taken` 集合は先に走った区分が後続の代表例を奪う。** 述語の緩い大区分を先に走らせると、
   希少区分の唯一の代表例が消える。実例: 主要4業態の補充枠が
   `令和8年2月度チェーンストア販売統計` / `コンビニエンスストア統計調査2月度` を先取りし、
   `no_numeric` 区分に月次統計行が 1 件も残らなかった。

3. **「区分が空洞化していないか」は件数では見えない。** 確認すべきは
   「発表主体並立」区分なら**相方の行が同じ fixture に入っているか**（片側だけでは
   2 レコード共存を書けない）、「複数指標」区分なら**対象内の行か**、
   「連続記録」区分なら**実際に `Nカ月ぶり` を含むか**。

**Why:** G1 は「偏りが評価を無効化するため機械的に決める」と言うが、機械的＝無作為ではない。
決定論的なタイブレークは再現性を与えるだけで、代表性は別途担保しなければならない。

**How to apply:** golden-60 系の diff では、母集団を復元して
「区分の述語を満たす母集団件数」「そのうち他区分に取られた件数」「区分内の
性質充足件数」の 3 つを実測してから採点する。関連: [[golden60-status]]。
